# 现有功能可靠性与性能修复计划

**Goal:** 修复评审中已复现的问题，优化现有操作，不添加产品功能。

**Architecture:** 保持 Electron、本地 JSON 和现有 IPC 接口。通过共享原子写入、资源引用迁移及统一搜索评分修复数据链路；保留现有未提交改动。

**Tech Stack:** Electron 31、JavaScript、Node.js、现有探针测试。

1. 保存：增加写入/替换失败测试，保证旧文件、缓存和撤销栈一致；修复设置和标注写入及错误提示。
2. 数据目录与备份：测试图片、网页快照、CSL 和托管附件；迁移引用、保护同名资源、失败回滚，兼容旧备份。
3. 搜索：修复独立笔记字段过滤和结果上限导致的漏项，统一相关性评分，减少重复读盘和线性查找。
4. 附件与展示：修复未保存 DOI、下载后索引、重新定位后标注关联、无附件误报和中文姓名顺序；导出部分失败明确提示。
5. 列表：减少大库渲染成本，验证选择、双击、键盘、滚动及筛选行为。
6. 验证：运行新增故障回归及现有测试，记录性能对比；最小更新文档。所有数据测试使用临时目录，不操作真实用户库。
